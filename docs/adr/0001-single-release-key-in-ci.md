# 发布钥收敛到仓库 CI 一把

插件的信任完全来自 Ed25519 签名加 keyId：管理器拒绝未知 keyId 且没有 `--insecure`，而社区共建意味着代码来自陌生人。我们让**只有仓库 CI 持有的 `plugins-release` 私钥**签出的包才能进 catalog，贡献者在本地用自签钥自测，主机侧通过编译期内置或商城分发导入这一把公钥。

## Considered Options

- **每个贡献者一把钥，公钥提交进仓库 `trust/` 分发**：否决。信任面随贡献者人数线性膨胀，任一贡献者私钥泄露等于整个仓库的信任塌方。
- **流水线只构建不签名**：否决。管理器不认未签名的包，等于发布不出任何东西。

## Consequences

把信任收敛到一条供应链之后，"代码审核"才真的等于"信任边界"——审核不过的代码进不了签名环节。

代价：需要一份离线私钥备份和轮换/泄露预案；贡献者的本地包永远不会自动获得信任，自测必须在本地先信任自己的钥。
